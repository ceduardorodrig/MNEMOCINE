# Homelab Backlog Archive (Mnemocine)

> **History** of closed backlog items — the counterpart of the active queue in
> [`backlog.md`](backlog.md). The queue stays lean: only `open` / `in progress` / `blocked`
> items live there. A closed item (`resolved` / `discarded`) moves **here**, with its closing
> date, and its id leaves the document's `pending:` list. Canonized 2026-10-12.

## Governance

| Rule | Description |
|---|---|
| **One file per id** | An `HB-xxx` lives in `backlog.md` while open and in this file once closed — never in both. |
| **Closing date** | Every archived row records when it closed (the `Origin / Closed` cell carries a `YYYY-MM-DD`). |
| **Recurrence** | If the problem comes back, open a **new** item in [`backlog.md`](backlog.md) with `Recurrence: <this id>` and add `Recurred-by: <new id>` here. The pair is verified by `DOC-BACKLOG-RECURRENCE`. |
| **Ref is informational** | The `Ref` still points at the area document (the technical detail), but an archived item no longer requires a `pending:` declaration. |

> **Dynamic discovery:** `stenio --backlog --search <term>` greps this file and the active
> queue — a hit in **both** is a recurrence. Runbook:
> [`guides/backlog-routine.md`](guides/backlog-routine.md).
