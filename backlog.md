# Homelab Backlog (Mnemocine)

> **Active queue** — the single source of *pending* work for the homelab. It exists to end the
> dispersion: pending items used to live **hidden** inside each server/service doc. Now the
> *queue* lives here and the *history* lives in [`backlog-archive.md`](backlog-archive.md),
> while the technical detail stays in the matching doc. Canonized 2026-10-12 (v2: queue +
> archive + recurrence).

## Governance

| Rule | Description |
|---|---|
| **Single source** | Every open item has an **ID** here; the technical detail stays in the area doc (linked via `Ref`). |
| **Active only** | Only `open` / `in progress` / `blocked` live here. A closed item moves to [`backlog-archive.md`](backlog-archive.md) with its closing date. |
| **Required origin** | Every item states **when/how** it appeared (alert, finding, request). |
| **Close = archive** | On resolution, **update the technical doc**, **move the row** to the archive, and **drop the id** from the doc's `pending:`. |
| **New items open** | Nothing enters already "resolved". |
| **No new folder** | This file lives at the root of `mnemocine/` (the convention forbids new folders). |
| **Bidirectional link** | Every `Ref` here has a matching `pending: [HB-xxx]` in the target doc's frontmatter (and vice-versa). `stenio --scope homelab` (`DOC-BACKLOG-DRIFT`, `HOMELAB-BACKLOG-*`) enforces this. |
| **Recurrence** | If a closed problem comes back, open a **new** item with `Recurrence: HB-old`; the archive row gets `Recurred-by: HB-new`. Verified by `DOC-BACKLOG-RECURRENCE`. |

> **Linkage contract (the "living" part):** the backlog is the **index**; each doc declares its own
> pending items in the frontmatter field `pending: [HB-xxx, ...]`. The two sides must agree — that
> is what stops the backlog from rotting into a second, disconnected list. The **columns** are
> resolved from the table header, so the layout can grow without an engine change. See
> [`guides/backlog-routine.md`](guides/backlog-routine.md) for the weekly cadence.

### Severity

| Level | Meaning | Target |
|---|---|---|
| 🔴 **critical** | Data, security or availability at risk | immediate |
| 🟡 **medium** | Degradation, noise, technical debt with impact | days |
| 🔵 **low** | Improvement, cosmetic, housekeeping | whenever |
| 💡 **idea** | Proposal to evaluate (may become medium) | no deadline |

### States

**Queue:** `open` → `in progress` → `blocked` (what is missing). **Archive:**
`resolved` (with date) · `discarded` (with reason). An id lives in exactly **one** of the two files.

### Cadence

- **Weekly triage review**: reassess severity, close what is done, promote ideas.
- **Automated**: `hl-backlog-report.timer` (Mondays 09:00) audits traceability and pushes a
  digest to ntfy `/alerts` — open items by severity, the oldest open item, and any drift.
- `stenio --scope homelab` enforces the linkage (`DOC-BACKLOG-DRIFT`,
  `HOMELAB-BACKLOG-MALFORMED`, `HOMELAB-BACKLOG-LIFECYCLE`, `HOMELAB-BACKLOG-STATE`,
  `DOC-BACKLOG-RECURRENCE`) and this file's frontmatter.
- `stenio --backlog` lists the queue; `stenio --backlog --search <term>` greps the queue **and**
  the archive (find recurrences). Runbook: [`guides/backlog-routine.md`](guides/backlog-routine.md).
